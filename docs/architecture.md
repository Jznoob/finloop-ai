# 架构与关键取舍 · v0.3

## 运行关系

```text
浏览器 ─ POST /jobs + Idempotency-Key ─ SQLite 接收任务
                                            │
                                 单进程执行器（并发 2）
                                            │
                                  每次尝试独立 run_id
                                            │
             ┌── 关键词洞察 ──┐             │
任务输入 ────┤               ├─ 上下文预算 ─ 策略 ─ 内容 ─ 规则闸门
             └── BM25/制度 ──┘                            ├─ 阻断
                    │                                    └─ 模拟执行
                证据原文快照                                    │
                                                      结果 + 记忆原子提交
                                                              │
                    实验室 ─ 独立报告（不学习）          唯一复核 ─ 偏好权重
```

这是六个领域模块与知识服务组成的显式工作流，不是七个自主 LLM 的群聊。洞察和检索并行；之后按序执行。仅策略/内容可接远程模型。PipelineEvent 提供阶段、序号、时间和结构化负载，失败尝试的日志也保留。

## 持久任务与一致性

jobs.idempotency_key 有唯一约束。相同键按排序后的 JSON 比较输入，不同输入返回冲突。比较的是脱敏后的规范输入。任务通过条件 UPDATE 原子领取，领取和 job_attempts 日志处于同一事务。

单任务超时 90 秒、最大并发 2，asyncio 任务持有强引用。客户端断线不取消服务端任务；页面轮询重连。重试创建新 run_id，不覆盖旧事件。

完成结果与新记忆在一个 SQLite 事务内提交。若进程在结果提交后、任务状态更新前退出，启动恢复以已提交结果为准。没有结果的活动任务标记为中断，排队任务恢复调度，不受最近 100 条历史的展示上限影响。

限制：单进程假设，没有分布式租约或节点级恢复。真实渠道需要 Outbox、消费者幂等和审批，当前没有外部触达副作用。

## 检索与证据护照

中文二元词和英文词项 → 段落 BM25 → 每文档取最高段落分 → Top-K。排除尚未生效的文档，无词项重合时返回空。分数是排序归一化值，不是概率或语义置信度。

业务任务检索 Top-2 后显式固定载入 CMP-001、SUT-002、PRD-DEMO。检索评测只测原始 Top-2，不把固定制度算入召回。

检索与快照共用一次读取的文档集合，避免引用旧版却保存新版。SHA-256 包含 ID、标题、类别、来源、生效日、原文。护照保存原文、指纹、输入/上下文哈希、记忆 ID、种子与规则版本。

完整性检查分别输出 snapshot_integrity 和 current_matches。这不是数字签名，不抵御有数据库写权限的恶意修改，也不是逐句事实检测。

## 上下文与模型网关

PII 正则先处理身份证，再处理手机号和邮箱；输入和复核备注在落库前处理。上下文按必选性与优先级装箱，装箱预算包括标题/分隔符。必选区块可截断，可选区块不足时丢弃。估算为一个汉字一单位，其他字符约四字一单位，不是实际 tokenizer；不包含完整模型请求中额外的系统提示和节点元数据。

显式场景规则将沉默激活、多资产、波动与通用教育分开，场景同时影响洞察、建议行动和本地文案。内容节点接收已选策略及其角度，避免“选择了策略但生成节点没有使用”。这是可测试的规则基线，不是对真实客户意图的自动识别。

网关检查 JSON 包含必需的非空字符串并限制单字段长度。调用轨迹区分 local-template、remote-success、fallback:invalid-schema、fallback:provider-error。每次运行用独立 ContextVar 收集，不混合并发记录。

策略与内容提示词分别带有显式版本号，并写入证据护照。模型诊断接口只在用户主动触发时发起一次最小结构化请求，返回经过脱敏的状态、耗时与失败类别，不保存响应内容。它验证的是接口与结构兼容性，不代表业务输出质量。

## 决策差异复盘

对比服务只读取两条已完成运行，不重新执行模型或写入学习数据。它分别比较核心输入、随机种子、证据集合及内容指纹、提示词版本、模拟器版本、实际策略、模型轨迹和漏斗指标。

只有核心输入、种子、证据、提示词和模拟器全部一致时才标记“强可比”；核心输入一致但版本不全时为“部分可比”，其余为“情境对照”。分级用于防止把不可比的两次输出直接归因于策略。远程模型可能存在非确定性，因此强可比也不等同于因果识别。

## 记忆治理

| 类型 | 来源 | 边界 |
| --- | --- | --- |
| episodic | 一次模拟运行及漏斗 | 不是真实客户经验 |
| semantic | 客群/产品目录规则 | 不是自主提炼知识 |
| procedural | 固定流程规则 | 不是自主学习制度 |

ID 基于 namespace、类型、内容生成。召回按词项重合、重要度、时间衰减和类型增益排序，内容等价旧条目只召回一次。管理页按内容分组，不删除旧 ID；整组禁用后新任务停止召回，历史引用保留。

模拟结果不更新 review_arms。reviews.run_id 唯一约束与权重更新在同一事务，重复提交不累计。选择器是平滑均值加探索奖励的 UCB 风格启发式，不是带理论保证的标准 UCB1；学习的是复核偏好，而非真实转化。兼容 API 的 converted 字段在复核中表示认可。

## 实验室

每位虚拟用户固定消耗三个随机数：送达、打开、响应。更换策略不改变抽样序列，转化必须先打开。业务漏斗分母为送达人数，实验主指标分母为全部入组人数。

Wilson 区间对应每个策略；配对差异标准误来自同一用户两种二元结果之差的样本方差。只覆盖模拟抽样误差，不覆盖错误假设。正态近似在差异样本稀少时不稳健，多个比较未做多重性校正，不能作为显著性业务决策工具。

实验只新增 reports，不新增业务运行、记忆或权重；参数与计算方法随报告保存。

## 验证与后续

小语料回归与工程测试分开。评测使用临时 SQLite、独立 runtime、本地模板；业务数据库仅保存 API 触发的报告。升级时执行自动测试、类型检查、构建和页面验收。

下一阶段应先准备获得授权且独立标注的真实语料，再比较 BM25、embedding、重排的收益；真实模型质量/成本需要单独评估。分布式执行、租户权限、正式合规和模型注册表属于部署前工作，不作为已实现能力写入简历。
