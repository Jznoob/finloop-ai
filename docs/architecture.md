# 架构说明

## 1. 设计目标

FinLoop AI 的目标不是让多个角色互相对话，而是让每个决策都满足四个条件：

1. 可追溯：能回答“谁在什么上下文中，依据哪些文档，做了什么决定”。
2. 可恢复：运行状态和事件落库，智能体失败不会丢失完整上下文。
3. 可约束：适当性和合规属于确定性边界，模型不能绕过。
4. 可学习：结果进入记忆和策略选择器，下一次运行能利用历史反馈。

## 2. 运行时

`AgentRuntime` 是显式工作流，而不是开放式群聊。每一阶段都有类型化输入输出：

```text
INGEST ─┬─> INSIGHT ─┐
        └─> RETRIEVE ├─> CONTEXT ─> DECIDE ─> COMPOSE ─> GUARD
                       │                                  ├─> BLOCK
                       │                                  └─> EXECUTE ─> LEARN
                       └──────────────────────────────────────────────────┘
```

洞察与检索并行；策略、生成、合规与执行顺序进行。每次阶段变化都产生 `PipelineEvent`，包含序号、运行 ID、时间、智能体、阶段、状态、消息和结构化负载。结果和事件分别持久化，以支持快速读取与细粒度审计。

### 为什么不用“所有智能体共享一段聊天历史”

- 不同智能体需要的上下文不同，完整历史会带来成本和干扰。
- 合规智能体应该检查最终文案与证据，而不是继承生成智能体的推理倾向。
- 显式状态便于重放、评测、超时控制和生产监控。

## 3. 上下文工程

`ContextBuilder` 接收多个 `ContextSection`，每个区块声明：

- 名称；
- 优先级；
- 是否必选；
- 区块 token 上限。

组装过程先做手机号、邮箱和身份证号脱敏，再按“必选优先、优先级降序”装入总预算。必选区块超限时会截断，可选区块超限时丢弃。最终输出 `ContextTrace`，记录预算、实际估算、纳入/丢弃区块和脱敏次数。

生产增强方向：使用模型对应 tokenizer；为不同智能体配置独立预算；加入摘要缓存、证据时效和冲突检测。

## 4. 三层记忆

| 类型 | 记录内容 | 示例 | 召回作用 |
| --- | --- | --- | --- |
| episodic | 一次运行的事实与结果 | 某版本的打开率与转化率 | 提供相似任务先例 |
| semantic | 从多次事实提炼的稳定认知 | 稳健客群更关注回撤解释 | 补充客群画像 |
| procedural | 系统应该怎样做 | 先适当性、后生成、再合规 | 约束执行流程 |

召回分数由内容重合度、重要度、时间衰减和类型增益组成。记忆按客群 namespace 隔离，流程记忆允许使用 `global` namespace。

当前演示每次运行直接写入三条记忆。生产环境需要增加去重、合并、遗忘、反事实纠错、敏感字段策略和异步记忆巩固任务。

## 5. 知识检索

演示语料很小，因此采用无需外部向量数据库的融合检索：

1. 中文字/二元词和英文 token 化；
2. BM25 风格稀疏相关度；
3. 特征哈希生成 256 维稠密向量并计算余弦相似度；
4. 合规查询对制度与适当性文档增加领域权重；
5. 返回来源编号、标题、原文片段和归一化分数。

这种实现便于离线复现和讲解。生产环境可以把第三步替换为真实 embedding 与向量库，同时保留统一的 `Citation` 输出协议和评测集。

## 6. 安全与合规

合规闸门不依赖模型自评，依次检查：

- 禁止收益承诺和内幕暗示；
- 产品风险等级不得高于客群风险等级；
- 文案必须包含产品主要风险；
- 决策至少关联两条知识依据。

禁用表达属于可修复问题，替换并补充风险提示后状态为 `revised`；适当性倒挂和依据不足是不可修复问题，状态为 `blocked`，不会进入执行节点。

真实生产规则应由合规团队维护在版本化规则引擎中，并为规则变更、人工复核和申诉建立流程。

## 7. 反馈学习

创意选择器使用 UCB1 思路：后验均值负责利用，探索项对样本不足的版本加分。仿真结果和人工反馈都可更新 alpha/beta、曝光和转化计数。

这个模块故意与大模型解耦：即使使用不同模型，策略实验仍能用同一套统计口径评估。

## 8. 失败模式

| 失败 | 当前处理 | 生产建议 |
| --- | --- | --- |
| 模型超时或输出非法 JSON | 降级到确定性模板 | 重试、熔断、供应商切换 |
| 产品风险倒挂 | 合规闸门阻断 | 人工审批队列 |
| 知识依据不足 | 阻断执行 | 触发知识维护工单 |
| 重复执行 | 使用 idempotency key | Outbox + 消息系统去重 |
| 记忆污染 | namespace 隔离与类型标记 | 记忆验证、版本和删除机制 |
