# FinLoop AI 项目说明与使用手册

> 版本：v0.3
>
> 项目定位：面向金融营销场景的、可追溯的 AI 决策研究工作台
>
> 使用范围：本地演示、工程研究、实习作品集与面试讲解

## 1. 这个项目有什么用

金融营销类 AI 应用不应只解决“生成一段文案”。真正困难的是：系统为什么选择这条策略、引用了什么依据、规则是否允许执行、结果能否复现、失败后能否恢复，以及模拟结果会不会被误当成真实业务经验。

FinLoop AI 把这些问题组织成一个完整的决策闭环。用户给出目标客群、业务目标和市场信号后，系统会依次完成：

```text
输入任务
  ↓
识别客群与业务场景
  ↓
检索知识并固定制度依据
  ↓
选择沟通策略与演示产品
  ↓
生成渠道内容
  ↓
执行适当性、引用和禁用词检查
  ↓
模拟送达、打开与响应
  ↓
保存结果、证据、事件日志和记忆
  ↓
由人工复核决定是否更新策略偏好
```

它主要用于展示以下四种能力。

### 1.1 把 AI 输出变成可复查的决策

每次运行不只保存最终文案，还保存检索原文、文档版本指纹、上下文摘要、规则版本、随机种子、召回记忆和完整阶段事件。因此可以回答：

- 这段内容当时参考了哪些材料？
- 某篇知识文档后来是否发生变化？
- 哪些制度是检索命中的，哪些是系统强制载入的？
- 模型有没有被调用，失败时是否发生了本地降级？
- 某一步为什么被修订或阻断？

### 1.2 比较策略，而不是只展示单次生成

策略实验室会在同一组虚拟用户、同一组随机数上比较三种策略：清晰解释、证据优先和情景分析。这样可以减少由不同抽样带来的噪声，并观察市场压力、触达疲劳和样本量变化时，结论是否稳定。

实验会展示点估计、95% 区间和相对“清晰解释”的配对差异，但不会把模拟结果写回策略权重或长期记忆。

### 1.3 展示可靠的任务执行

任务在开始运行前先写入数据库。同一个幂等键和同一份输入不会生成重复任务；失败或中断后可以按原输入重试，每次尝试使用独立运行编号并保留历史日志。

这使项目能演示网络重传、刷新重连、失败恢复、并发去重和结果持久化，而不只是一次性页面效果。

### 1.4 展示受控记忆和人工反馈

系统把记忆分为情景记录、客群知识和固定流程，并记录来源。使用者可以禁用或恢复一组等价记忆；历史引用不会被删除。模拟漏斗不会自动训练策略，只有一条运行对应的唯一人工复核才会更新创意偏好。

这体现的是“可治理的应用记忆”，不是自主学习或真实客户画像系统。

## 2. 适合怎样使用

### 2.1 实习作品集

项目适合用来证明你能够把 AI 能力放入完整软件系统，而不只会调用一次模型接口。可重点展示：

- 显式 Agent 工作流与结构化输入输出；
- 检索、证据快照和版本核验；
- 上下文预算、PII 脱敏与模型失败降级；
- 异步任务、幂等、事务和失败重试；
- 可复现实验、隔离评测和人工反馈治理；
- FastAPI、SQLite、React、TypeScript 的全栈实现。

### 2.2 面试现场演示

推荐把重点放在“为什么这样设计”和“如何证明它没有偷偷污染数据”。不要只展示最终生成的文案，也不要把模拟转化率当成真实业绩。

### 2.3 本地研究原型

可以把它作为以下研究的基线：

- 比较 BM25、向量检索和重排模型；
- 接入真实模型后评估生成质量、成本和延迟；
- 扩展更严格的金融内容规则；
- 将模拟实验替换为获得授权的离线数据分析；
- 将单进程执行器升级为分布式任务系统。

## 3. 项目不是什么

为避免误用，需要明确以下边界：

- 它不是投资顾问系统，不提供投资建议；
- 它不是已上线的金融营销平台，没有真实客户和真实触达；
- 页面中的产品、客群、送达、打开和响应数据均为虚构或模拟；
- 规则通过只表示演示规则通过，不代表正式法律合规；
- 证据可追溯不等于每句话都已被事实蕴含；
- SHA-256 用于版本一致性检查，不是防篡改数字签名；
- 默认检索是段落 BM25，没有使用向量 embedding；
- 默认内容来自确定性本地模板，未配置密钥也能完整演示；
- 当前没有登录、租户、权限、限流、分布式队列或真实渠道连接。

不要向系统输入真实客户资料，也不要把它直接暴露到公网。

## 6. 最快上手：完成一次决策任务

打开“运行工作台”，按以下步骤操作。

### 第一步：选择演示场景

系统提供三个预设：

| 预设 | 适合展示的能力 |
| --- | --- |
| 波动应对 | 回撤咨询增加时的风险解释与稳健产品适配 |
| 沉默激活 | 打开率下降时的低负担触达和暂停接收选项 |
| 多资产教育 | 相关性变化与海外波动下的多资产风险说明 |

也可以手动选择客群，修改“业务目标”和“市场信号”。

### 第二步：设置实验参数

展开“实验参数”：

- **创意策略**：选择自动、清晰解释、证据优先或情景分析；
- **随机种子**：相同输入、相同策略和相同种子会得到可复现的模拟样本。

首次演示建议选择“波动应对”、种子 `42`，策略保持“由复核权重选择”。

### 第三步：创建并运行

点击“创建并运行”。页面会显示洞察、知识、决策、内容、合规、执行和反馈七个阶段。任务已经持久化，因此运行过程中可以切换页面；刷新后仍能从“运行历史”找回。

### 第四步：查看内容与规则

运行完成后，“内容与复核”页签会展示：

- 最终渠道内容；
- 使用的客群、渠道和创意策略；
- 模拟的样本、送达、打开和响应漏斗；
- 每条规则的检查结果；
- 原稿是否经过自动修订；
- 人工质量复核入口。

模拟漏斗只用于检查闭环行为。页面中的“转化”不是实际客户转化，也不会自动更新策略权重。

### 第五步：检查证据护照

进入“证据护照”页签，重点查看：

- 文档编号、标题、来源和运行时原文；
- “查询检索命中”与“制度强制载入”的区别；
- 保存快照是否完整；
- 当前知识库版本是否仍与当时一致；
- 文档内容指纹、输入摘要和上下文摘要；
- 被纳入或因预算不足而丢弃的上下文区块；
- 该次运行召回了哪些记忆。

点击来源卡片可以查看原文。文档以后发生变化时，旧任务仍保留当时使用的版本。

### 第六步：查看运行轨迹

进入“运行轨迹”页签，可检查：

- 每个阶段的开始、完成、修订或阻断状态；
- 阶段事件的时间和结构化负载；
- 模型调用结果；
- 是否使用本地模板，或远程模型失败后发生降级。

本地默认模式会显示 `local-template`，这是预期行为，不代表接口故障。

### 第七步：提交人工复核

返回“内容与复核”，选择 1～5 分，并判断是否认可策略。每条运行只能成功提交一次复核，重复请求不会重复更新权重。

复核表达的是内部质量偏好，不是真实业务转化标签。

### 第八步：导出结果

点击“导出运行 JSON”，可以保存本次运行的请求、结果、证据、事件和上下文记录，适合代码检查或面试讲解。

## 7. 八个页面分别怎么用

### 7.1 运行工作台

用途：创建任务、观察完整流程、检查输出、规则、证据和事件，并提交人工复核。

建议先从这里产生一条完成的运行，其他页面中的实验、记忆和历史功能会更容易理解。

### 7.2 策略实验室

用途：回答“如果保持同一批虚拟用户，只改变策略，会发生什么”。

操作方法：

1. 选择一条已完成且含模拟执行结果的基线运行；
2. 设置样本人数，允许范围为 200～5000；
3. 设置随机种子；
4. 调整市场压力和触达疲劳；
5. 点击“运行同样本对比”；
6. 比较三种策略的点估计、Wilson 区间和配对差异区间；
7. 展开模拟假设与计算方法，确认结论依赖哪些人为设定。

正确解读方式：

- 差异区间跨过 0，表示当前模拟下没有足够清晰的差异证据；
- 区间不跨 0，也只能说明这套模拟假设下存在差异；
- 增加样本量通常会缩小抽样区间，但不会修正错误的业务假设；
- 市场压力和疲劳是敏感性分析参数，不是从真实数据估计出的因果变量；
- 实验报告会保存，但不会新增业务运行、记忆或策略权重。

### 7.3 决策对比

用途：回答“两次运行为什么不同”，并先验证这两次结果是否具备可比条件。

操作方法：

1. 选择一条基线运行和一条对照运行；
2. 点击“分析决策差异”；
3. 先查看“强可比”“部分可比”或“情境对照”；
4. 检查客群、目标、信号、种子、策略和模型路径；
5. 检查证据是否新增、移除或发生内容版本变化；
6. 最后比较模拟漏斗、内容相似度与复盘结论。

如果想观察策略本身的影响，推荐在工作台使用完全相同的客群、目标、市场信号和随机种子，分别指定两种策略后再比较。远程模型即使条件相同也可能产生非确定输出，因此这里不宣称真实因果效果。

### 7.4 证据知识库

用途：检查系统能搜索哪些演示制度和产品知识，以及无相关依据时是否会返回空结果。

可以搜索“风险等级倒挂”“触达疲劳”“身份证号脱敏”等关键词。结果中的分数只用于排序，不是模型置信度。

建议再输入一个明显无关的查询，观察系统返回空结果，避免把任何文档都包装成“相关证据”。

### 7.5 记忆管理

用途：查看系统在后续任务中可能召回的内容，并控制其是否继续生效。

记忆类型：

| 类型 | 含义 | 真实边界 |
| --- | --- | --- |
| episodic | 某次模拟运行与漏斗摘要 | 不是实际客户经验 |
| semantic | 客群或产品目录规则 | 不是模型自主提炼 |
| procedural | 固定流程或政策 | 不是模型自行学习制度 |

同内容的历史记录会折叠显示。点击“禁用”会让整组等价内容停止参与新任务召回，但不会删除旧数据；点击“恢复”可重新启用。

可用以下方法验证治理是否生效：

1. 在记忆管理中禁用一条相关记忆；
2. 返回工作台创建一条新任务；
3. 打开新任务的证据护照，检查召回记忆 ID；
4. 回到记忆管理恢复该记忆。

### 7.6 质量评测

用途：运行一套独立回归，验证正常流程和失败边界。

点击“运行评测”后，系统会使用临时数据库和本地模板运行 18 项用例，包括：

- 三类完整流程场景；
- 相关与无关检索查询；
- 伪造引用、产品风险倒挂和禁用词；
- PII 脱敏与极小上下文预算。

评测不会增加工作台的业务运行、长期记忆或策略权重。报告中的小语料检索指标用于防止代码回归，不代表真实金融检索水平。

### 7.7 运行历史

用途：查看任务状态、找回结果和处理失败任务。

- “查看结果”会返回工作台并打开对应运行；
- “尝试次数”会展开每一次尝试及其阶段事件；
- 失败或中断任务会显示“重新运行”；
- 重新运行保留原输入和旧日志，但会生成新的运行编号；
- 下方搜索框可以按目标、客群或运行编号查找已保存结果。

### 7.8 运行配置

用途：查看服务端当前真实能力，包括模型提供方、密钥是否配置、上下文预算、执行器、失败恢复、检索和学习方式。

页面不会把服务端密钥返回给浏览器。这里适合在演示结束时说明系统边界。

配置页还提供“测试当前模型连接”：本地模式只验证本地回退；远程模式会发起一次最小 JSON 请求，并显示远程成功、连接失败或结构不兼容。远程探测可能产生少量调用费用，只有点击按钮才会执行。

## 8. 接入兼容模型

项目默认使用 `deterministic` 本地模板，不需要密钥。若要测试兼容 Chat Completions 的远程模型接口：

```bash
cd /Users/hannn/project/finloop-ai
cp .env.example .env
```

编辑 `.env`：

```dotenv
FINLOOP_MODEL_PROVIDER=openai-compatible
FINLOOP_MODEL_NAME=你的模型名称
FINLOOP_API_KEY=你的密钥
FINLOOP_BASE_URL=兼容接口的基础地址
FINLOOP_DATABASE_PATH=./data/finloop.db
FINLOOP_CORS_ORIGINS=http://localhost:5173
```

保存后重启服务。密钥只应放在本地 `.env` 中，不要提交到 Git。

当前只有策略与内容阶段可以调用远程模型。响应必须是包含所需非空字段的 JSON；如果接口报错、返回非 JSON 或字段校验失败，系统会改用本地模板并在运行轨迹中记录降级原因。

接入远程模型后仍需单独检查：

- 输出质量与规则稳定性；
- JSON 兼容性；
- 超时、限流与重试行为；
- 单次任务的 token 成本；
- 敏感数据处理和供应商条款。

## 9. 使用 API

浏览器操作已经覆盖主要流程。需要脚本集成时，推荐使用持久任务接口。

### 9.1 创建任务

```bash
curl -X POST http://127.0.0.1:8000/api/jobs \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: guide-demo-2026-001' \
  -d '{
    "segment_id": "steady-planner",
    "objective": "解释市场波动与配置纪律",
    "market_signal": "市场波动放大，回撤咨询增加",
    "dry_run": true,
    "seed": 42,
    "variant": "clarity"
  }'
```

响应状态为 `202`，其中包含任务 ID。同一幂等键和相同输入再次提交会返回同一任务；同一键搭配不同输入会返回 `409` 冲突。

### 9.2 查询任务

```bash
curl http://127.0.0.1:8000/api/jobs/任务ID
```

任务完成后，从响应中读取 `run_id`，再查询结果：

```bash
curl http://127.0.0.1:8000/api/runs/运行ID
```

### 9.3 常用接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 检查服务与数据库状态 |
| POST / GET | `/api/jobs` | 创建任务 / 查看任务列表 |
| GET | `/api/jobs/{id}` | 查看状态、尝试与事件 |
| POST | `/api/jobs/{id}/retry` | 重试失败或中断任务 |
| GET | `/api/runs/{id}` | 获取保存的完整结果 |
| GET | `/api/runs/{id}/evidence` | 核验证据快照与当前版本 |
| GET | `/api/runs/{id}/export` | 下载运行 JSON |
| GET | `/api/knowledge/search?q=关键词` | 搜索知识库 |
| POST / GET | `/api/experiments` | 运行实验 / 查看实验报告 |
| GET / PATCH | `/api/memories` / `/api/memories/{id}` | 查看 / 启停记忆 |
| POST | `/api/feedback` | 提交唯一人工复核 |
| POST / GET | `/api/evals/run` / `/api/evals/reports` | 运行评测 / 查看报告 |
| GET | `/api/runs/compare?left=...&right=...` | 只读比较两次已保存运行 |
| POST | `/api/model/probe` | 主动执行一次模型兼容性诊断 |

`POST /api/runs` 是同步兼容接口，不经过持久任务队列。新客户端应优先使用 `/api/jobs`。

| 命令 | 检查内容 |
| --- | --- |
| `make test` | 后端单元/集成测试与前端单元测试 |
| `make lint` | Python 静态检查与 TypeScript 项目检查 |
| `make eval` | 使用隔离数据库执行质量回归 |
| `npm run build` | TypeScript 构建与正式前端打包 |

本版本最近的本地基线是：后端 39 项通过、前端 10 项通过、隔离回归 18/18。以后修改代码时应以重新执行后的结果为准。

如果面试时间有限，可以按以下顺序：

1. 用 20 秒说明：这是金融营销场景的可追溯决策工作台，重点不是生成文案，而是证据、实验和恢复。
2. 在工作台选择“波动应对”、种子 42，创建任务。
3. 展示最终内容和规则检查，明确漏斗为模拟数据。
4. 打开证据护照，查看一篇原文、内容指纹和“制度强制载入”标记。
5. 打开运行轨迹，说明事件日志和 `local-template` 模式。

8. 到记忆管理禁用一条记忆，说明新任务停止召回但历史仍保留。

10. 最后打开运行配置，执行本地模型诊断，并主动说明没有真实触达、正式合规和生产权限系统。

## 12. 面试时如何概括

可以使用下面这段介绍：

> FinLoop AI 是一个面向金融营销场景的可追溯决策研究工作台。我把客群洞察、知识检索、策略选择、内容生成、规则检查、模拟执行和人工反馈组织成显式工作流。系统会保存运行时证据原文和版本指纹，通过同样本模拟比较策略，并用幂等任务、事务提交和尝试日志处理重传与失败恢复。模拟结果不会自动训练策略，只有唯一人工复核会更新偏好。项目默认离线可运行，也可以接入兼容模型接口，但它不是生产投顾或真实营销平台。

被追问时，重点讲清以下取舍：

- 为什么小语料先用可解释 BM25，而不是为了技术名词强行加入向量库；
- 为什么来源可追溯和事实正确是两个不同问题；
- 为什么实验与模拟不能直接写入学习数据；
- 为什么“请求幂等”不等于真实外部渠道 exactly-once；

## 13. 常见问题

### 页面显示“等待服务连接”怎么办？

确认后端仍在运行，并打开 <http://127.0.0.1:8000/api/health>。开发模式还要确认前端运行在 5173 端口。页面会自动重连，不需要清空数据库。

### 为什么没有调用真正的模型？

默认使用本地模板，让工作流、证据、存储、规则和实验在无密钥环境中也能稳定复现。需要时可以按第 8 节配置远程模型。

### 为什么相同种子的实验结果一样？

这是为了可复现。同一批虚拟用户使用固定随机序列，策略比较不会因为重新抽样而产生额外噪声。

### 为什么检索有时返回空结果？

系统要求查询与文档有词项重合。无关查询返回空比强行返回一篇“看似相关”的文档更诚实。

### 为什么同一条运行不能重复复核？

为了防止浏览器重传或重复点击多次更新策略权重。数据库会保证一条运行最多有一条有效复核。

### 重试是从失败节点继续吗？

不是。当前实现会保留旧尝试日志，并使用原输入完整重跑，生成新的运行编号。它不是节点级 checkpoint。

### 可以用于真实业务吗？

不能直接使用。上线前至少需要真实且获授权的数据评估、正式合规审查、身份与租户权限、分布式执行、审计与监控、模型注册、真实渠道审批和隐私安全设计。
