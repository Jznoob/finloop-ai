# 面试讲解指南

以下描述适合在你已理解、亲自演示和复现实现后使用。不要把模拟指标写成真实增长，不要声称已生产落地。可以如实说明使用 AI 编程辅助，并讲清自己验证和作出的取舍。

## 30 秒介绍

FinLoop AI 是金融营销场景的决策研究工作台。我围绕“结果能否解释、实验是否可信、失败是否可恢复”设计显式 Agent 工作流。运行保存原文证据与版本指纹；实验室在同批虚拟样本上比较策略并展示不确定性；任务通过幂等键和持久状态实现失败重试，每次尝试都有日志。模拟数据不更新策略，唯一复核才更新偏好权重。默认离线可运行，能选配模型，但不是生产投顾系统。

## 现场演示重点

1. **来源变化不抹掉历史。** 护照中的“快照完整”和“当前版本一致”是两个检查；测试会在运行途中修改知识库。
2. **实验不能自己制造业绩。** 同随机样本控制噪声，显示分母和区间；数据库前后状态断言实验、评测不写入业务学习数据。
3. **幂等不是生成一个字符串。** 服务端唯一约束和输入冲突检查，并发提交只产生一个任务；尝试日志与结果事务可解释恢复窗口。
4. **记忆可以撤回。** 固定知识去重，旧重复记录不删除、不重复召回，禁用后新任务停止使用。

## 简历条目候选

**FinLoop AI｜可追溯金融营销 Agent 决策工作台**

- 实现类型化多模块工作流，串联客群洞察、段落 BM25、策略选择、内容生成、适当性规则和模拟执行，支持事件日志与可选模型降级。
- 设计证据护照，保存运行时原文、SHA-256 指纹、规则版本与记忆引用，区分历史快照完整性和知识版本变化。
- 实现同样本策略比较及隔离评测，提供区间与统计口径，验证模拟结果不污染业务记忆或策略权重。
- 使用 SQLite 唯一约束、原子提交、后台执行器实现请求幂等、失败重试、尝试日志与单次复核保护，提供 React 工作台及自动回归。

测试基线见 verification.md，以重新执行输出为准。不建议突出小语料集的“100% 召回率”。

## 追问准备

### 这是真正的多智能体吗？

准确说是职责隔离的多模块 Agent 工作流。策略和内容可调用 LLM，其余是规则、检索与执行服务；没有包装成七个自主模型。重点是输入输出契约、并行边界以及规则改变控制流，不是角色数量。

### 为什么不直接使用 LangGraph？

小规模显式工作流便于解释一致性与事件设计，也减少依赖。代价是没有成熟图框架的 checkpoint、分布式调度与调试能力；规模上来后应重新评估框架，而非坚持自研。

### 引用存在就证明答案正确吗？

不证明。只能检查来源、版本、固定制度存在并发现伪造编号；不能证明句子由证据支持。下一步需要命题拆分、支持判定、负例集与人工抽检。

### 为什么没有向量库？

8 篇文档不足以证明向量库收益，先使用可解释 BM25 基线。特征哈希不等于语义 embedding，新版移除了夸张表述。先准备授权且有独立标注的语料，再开展对照实验。

### 记忆与学习有什么区别？

情景来自模拟，客群知识来自目录，流程来自固定规则；实现的是存储、召回、去重和禁用，不是自主巩固。创意选择只接受唯一复核标签，UCB 风格分数不是转化概率，人工偏好不能代替业务回报。

### 重启为什么不会重复触达？

项目没有真实触达，只能说明请求层幂等与结果提交一致性。外部渠道不能直接承诺 exactly-once，需要事务 Outbox、渠道幂等、投递确认与人工审批。

### 项目最初有哪些不足，你如何修正？

旧版用模拟反馈更新策略，检索语料过小且指标漂亮，界面主要展示单次运行。新版分离模拟与复核，固定制度不计入检索指标，加入无关查询和失败测试，补全证据、实验、记忆、恢复的操作闭环。可验证的修正比宣称“全面生产级”更有说服力。
