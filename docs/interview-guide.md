# 面试讲解指南

## 30 秒版本

FinLoop AI 是我针对金融营销场景做的可审计多智能体闭环。它把市场信号和客群目标交给洞察、知识、策略、内容、合规、执行和反馈模块，先做适当性再生成内容，并通过独立合规闸门控制执行。每一步都有事件轨迹和知识引用，执行结果会更新创意 bandit 与三层长期记忆。项目默认离线可运行，配置兼容接口后也可以接真实模型。

## 3 分钟版本

### 1. 问题

传统营销自动化的规则固定，普通 Agent Demo 又容易只展示生成效果，缺少适当性、审计和反馈学习。我希望同时证明 Agent 架构能力与金融工程意识。

### 2. 架构

运行时不是群聊，而是一张显式工作流。洞察和知识检索并行，之后按策略、内容、合规、执行、反馈顺序推进。每个节点只接收它需要的结构化状态，所有状态变化写入事件表。

### 3. 两个重点

- 上下文工程：不是把全部历史塞给模型，而是给每个区块设置优先级、必选属性和 token 上限，先脱敏再按预算装箱，同时输出可观察的 context trace。
- 记忆：把一次运行、稳定认知和执行规则分为 episodic、semantic、procedural 三类，并按相关度、重要度和时间衰减召回。

### 4. 金融安全

产品风险等级先于生成被过滤。最终内容还要经过独立、确定性的合规闸门；可修复表达会自动改写，适当性不匹配直接阻断。执行默认是仿真，并用幂等键避免重复。

### 5. 验证

仓库包含单元、API 和端到端测试，以及三个场景的离线评测。当前基线为 3/3 通过、知识引用召回率 100%、适当性 100%，同时明确说明这不等同于线上业务收益。

## 高频追问

### 为什么没有直接用 LangGraph/CrewAI？

这个项目需要展示核心架构设计，所以我自己实现了状态、事件、上下文、记忆和安全边界。接口是模块化的，后续可以把运行时替换为 LangGraph 或 Microsoft Agent Framework，但领域模型和评测不需要重写。

### 这是真的多智能体吗？

“多智能体”的价值不在角色数量，而在职责、上下文和失败边界是否隔离。这里每个模块有独立输入输出、置信度、产物和事件；洞察与检索可并行，合规可以改变控制流，反馈会影响后续策略，因此不是提示词角色扮演。

### 为什么合规不用模型？

模型可以辅助解释，但硬边界不能只靠概率输出。风险等级、禁用表述、风险披露和引用数量用确定性规则保证最低安全线；生产中再叠加正式规则引擎和人工审批。

### 哈希语义向量不是伪 embedding 吗？

它是为了让仓库在无模型、无向量库条件下仍可复现的语义近似基线，不声称达到 embedding 模型效果。检索服务的输出协议已经固定，可以无缝换成真实 embedding，并用同一评测集比较收益。

### 上生产还缺什么？

需要真实 IAM 和数据权限、密钥托管、可版本化规则引擎、人工审批、模型和提示词注册表、异步消息系统、分布式 tracing、SLA、线上实验平台，以及与持牌机构制度一致的合规评审。
